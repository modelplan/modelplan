The Antigravity reader could find no running server on macOS: beside the full command line, `ps` prints a process's `comm` as the first 16 characters of its executable path, which never matched. The server's name is now also read from its command line, and newer hub-mode servers (Antigravity 2.3x), which keep their port and transport nonce off the command line, are found through the discovery file they write under `~/.gemini/<app data dir>/daemon/`, accepted only when its pid is this user's running Antigravity language server and the loopback listener belongs to it (#1175). When no server can be verified, the Antigravity Settings row now says so and offers to open the app instead of asking for Node.js, which this native reader never uses.

The past-usage import now also reads Codex's archived threads (`archived_sessions`), so archiving a thread no longer hides its usage; Codex history imported by an earlier version is read again once from both folders. After the first-run import was requested, a Claude Code or Codex history that is still not imported (the run failed, was interrupted or its permission was withdrawn, or its history was cleared and then allowed again) is imported when the engine starts or after the next permission change. Automatic imports read only tools whose history you allowed explicitly; a fresh profile still waits for the first-run consent (G3-112). `modelplan doctor readers` lists `codex:history` and `claude:history` with the import's coverage, reports a GLM key-file reader that has never read as `unavailable:not_read` instead of `stale`, and a signed-in Cursor account on the free or hobby plan as `no_plan` instead of `schema_changed` (G3-117). ZCode installed only as the CLI community package (`~/.local/share/zcode-community`, `~/.local/share/zcode-cli`) or the macOS support folder without a provider file now shows "This saved sign-in is not supported" instead of waiting for a first reading forever, also under a bare legacy GLM permission. The public `readerErrorCode` schema now lists `codex_custom_provider`, `team_unsupported` and `policy_pending`, which the CLI already emits.

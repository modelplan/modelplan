# Settings model layer

MIT; macOS 14+. This package contains state, persistence, page data and consumer projections. It has no view, drawing code, native service calls, process runner or network client. The lane-local package depends on the existing public dock logic. App-target registration remains with the assembly owner.

```
swift test --package-path desktop/native/ModelPlanSettings --jobs 2
```

The current eight-page and three-step content is **provisional**; it is not a final Settings/first-run freeze. `SettingsStructure.provisional` and `OnboardingDefinition.provisional` are replaceable data inputs.

The desktop CI runs this suite on macOS 14 and the newest hosted macOS image. Its F15/F20-style inputs are synthetic: no private assets, account observations or design checkout are needed. This is logic acceptance, not visual or real system-service acceptance.

## Persistence and consumers

- Create one app-scoped `SettingsStore` at an app-owned **new** preference URL. This v1 envelope does not replace Core's existing `CommunityPreferences` file (locale/favourites). M0 must choose one authoritative locale when binding them; do not introduce two simultaneous writers. Preferences contain choices and stable subscription IDs/aliases, never raw CLI data, observed login status or authorization status.
- `update(expectedRevision:_:)` validates a complete candidate and writes a bounded, private staging file before atomic replacement. Failed validation/write leaves the previous value/revision in memory; unsupported, corrupt and oversized files fail without being reset or overwritten. Missing v1 top-level choices use defaults. Obsolete/malformed onboarding progress is reconciled independently to the supplied flow in memory, without resetting unrelated preferences or rewriting the file during load. There is no migration from another file or cross-process write coordination. A caller should present load errors rather than open another store and silently reset it.
- Supply the same `OnboardingDefinition` to the store initializer and onboarding reducer. After standalone decoding, call `reconcile(in:)` before presenting a flow. Pass each committed snapshot to `EffectiveSettings`, `SettingsCatalogue`, the shortcut matcher and notification policy. Re-evaluate with current system appearance/accessibility/full-screen inputs. A preference override can force reduced effects on, not force system accessibility off.
- `SettingsPreferences.subscriptions` reuses `DockSubscriptionPreferences`; Settings, dock and cockpit share this same order/hidden set, including disconnected IDs. `presentedSubscriptionIDs(includingHidden: true)` keeps hidden subscriptions editable. Alias drafts do not commit marked IME text.
- `EffectiveSettings.visibilityPolicy` and `applying(to: DockPresence)` feed the existing dock reducer. `SettingsPreferences.applying(to: DockInstrumentInput)` supplies alias, remaining/used mode and general-window pin. Pass `redBelow` to `DockInstrumentProjection.evaluate`; critical status always uses remaining quota. An unavailable pinned period falls back to the dock's automatic selection; no window is fabricated. Number visibility does not remove event indicators; `showPercentages` is a separate consumer flag.
- Other effective choices (size, magnification, menu display, language, active-display following, names, sliver alert) are typed inputs for their eventual consumers. M0 owns real locale/display/service binding and redraw transactions. No runtime effect is claimed until these adapters exist.
- Product ignition remains quick-only on macOS 14, under Reduce Motion or until the native entrance is accepted. The stored hold choice survives a capability downgrade. Default accepted product ignition is 950 ms; the optional tutorial gesture is a separate 800 ms lesson. First-run state derives its initial/current/final step, next/back/completion, demo eligibility and resume/replay from one injected `OnboardingDefinition`; the provisional table has the existing three steps, but a supplied one-step flow uses the same reducer. Stable content IDs and an order/capability signature prevent obsolete completion from skipping a changed flow; missing draft signatures are accepted only for the original provisional definition. Legacy draft integer IDs remain readable. No project-name consent step or reader action is added.

## Actions and read-only data

The catalogue provides English/Chinese search, one-line titles/subtitles, choices, per-subscription data and explicit availability. Search includes both languages plus subscription alias, plan, vendor, tool and model names. A validated `SettingsStructure` supplies ordered pane IDs/titles, groups and setting keys independently of the preference/value definitions. Custom pane IDs, regrouping and reordering require no reducer changes; all existing keys must appear exactly once. Rows carry the injected pane/group identity and titles, and search also includes these injected titles. The provisional input preserves the original eight-page content; it does not choose a final seven-page table. Duplicate vendors stay distinct by subscription ID/plan. Read-only source/CLI states are injected enums, never raw errors.

- Login reads the observed service state (initially not registered). `loginRequest` returns an intent only; it does not register anything or optimistically report success.
- Capture hiding stays unsupported. There is no preference switch claiming to hide from arbitrary recorders.
- CLI retention is read-only: sessions 35 days, daily totals 371 days. CLI clear, retention mutations and reader setup have no command/effect in this module.
- App-cache clear is a separate unavailable-by-default intent. Only enable it after an adapter can clear app-owned **derived caches**. It must retain preferences, aliases, order, consent, first-run progress, CLI history and the notification ledger; it must not reuse the browser study's preference-reset shortcut.
- Notification opt-in defaults off; per-kind choices alone do not grant consent. `userSetOptIn` returns one permission request only after an explicit off→on choice. Ignore late/mismatched replies. Denied/unavailable service states do not prompt in a loop. Persist the consent edit successfully before executing a returned permission effect; observe real authorization after changes.
- A notice must be live, within its semantic episode's lifetime, and have a stable subscription/episode ID. Restored/replayed snapshots do not notify. Deduplication uses kind+subscription+episode, not changing receipt times/revisions. The bounded `NotificationLedger` contains only opaque IDs/deadlines and can be stored as a separate app-owned file. Restore it before live delivery; use bounded decoding at that adapter boundary. Serialize evaluate/send/record, recheck consent/deadline immediately before sending, and record only OS-accepted deliveries. At capacity the policy suppresses new events rather than evicting live deduplication entries. Hidden project names never appear in the returned delivery. No notification is actually scheduled by this package.
- About diagnostics allow only version tokens and capability/architecture enums; no paths, aliases, project names, IDs or raw CLI output. Feedback is a public issue-template URL, not an automatic submission. The app supplies audited bundled third-party license notices. Intel carries the explicit untested warning.

## Deferred to native binding

No window/sidebar/pop-up, command-comma registration, global shortcut registration, login item change, notification permission request, actual cache deletion, accessibility focus or IME event handling is executed here. Those need app adapters and the corresponding native acceptance, including actual minimum-OS/service states. This package does not release any visual freeze gate.

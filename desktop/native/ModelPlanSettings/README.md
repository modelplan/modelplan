# Native Settings and model layer

MIT; macOS 14+. This package contains state, persistence, page data, consumer projections and a neutral AppKit Settings window. It makes no native service calls and has no process runner or network client. The lane-local package depends on the existing public dock logic. App-target registration remains with the assembly owner.

```
swift test --package-path desktop/native/ModelPlanSettings --jobs 2
```

The current first run is the single-page `OnboardingDefinition.task65`; it has no tour or gesture practice. The confirmed task65 data table has eight panes in order: General, Dock, Cockpit, Appearance, Subscriptions, Notifications, Data & Privacy, About. Dock has Display/Numbers/Position/Order groups, and About stays independent. `SettingsStructure.task65` is the default; the old `provisional` table remains historical input for compatibility tests. This data-table decision is not a visual freeze.

The desktop CI runs this suite on macOS 14 and the newest hosted macOS image. Its F15/F20-style inputs are synthetic: no private assets, account observations or design checkout are needed. Model and offscreen AppKit checks do not establish desktop display, real-input or system-service acceptance.

## Native window integration

Create one `SettingsEditor` over the app's existing `SettingsStore`, then retain one `SettingsWindowController` for it. `await controller.present()` loads current state and opens the native window; it does not activate the application. The app owns the gear/menu/Command-comma route and activation/focus policy. Constructing/preparing the controller does not show a window.

The sidebar uses the eight canonical panes and initially selects General; bilingual search includes pane/group text and subscription metadata. `SettingsB20Edit` covers appearance and Dock number choices. `SettingsB21Edit` adds Dock behavior/position/order, General, opening/countdown and subscription choices. Notifications, privacy, About actions and the first-run view remain unavailable. No system login, global shortcut, reader, updater or cache action is executed. Controls retain native identities while values/appearance change. The five line diagrams retain their finite400ms movement and static reduced-motion behavior.

Only the current control owned by a displayed row may submit an edit. Pane/search removal and subscription-control replacement permanently disable retired controls, clear their callbacks and cancel menu tracking; a delayed target/action or accessibility press cannot save through them. Rows retained by a search/environment update keep their existing control and focus identity.

```swift
let editor = SettingsEditor(store: appSettingsStore, context: subscriptionContext)
editor.onCommit = { snapshot, effective in
    // Forward this committed revision to the app's existing Dock/Cockpit renderers.
    applySettings(snapshot, effective)
}
editor.onEnvironmentChange = { snapshot, effective in
    // Recompute/redraw current consumers without saving a preference.
    applySettings(snapshot, effective)
}
let controller = SettingsWindowController(editor: editor, environmentProvider: currentSettingsEnvironment)
await controller.present()
```

The host supplies one authoritative environment including fullscreen/entrance gates, system appearance, Reduce Motion, Reduce Transparency and Increase Contrast. The default provider reads only OS appearance/accessibility preferences; an app with additional gates should inject its own provider. Workspace accessibility changes and app appearance changes request a fresh environment. Update subscription context with `editor.update(context:)`; after external edits to the same store use `await editor.reload()`.

Edits await a revision-checked store transaction before `onCommit`; failed/stale saves emit no receipt and restore the latest committed value. Stale edits require a new explicit choice, rather than automatically overwriting another edit. The editor never opens a second file or service. Assembly must bind the callbacks to actual consumers: passing a model test or seeing a pop-up selection is not proof an open Dock/Cockpit updated.

Native tests never activate/order windows front. Optional `MODELPLAN_SETTINGS_EVIDENCE` points to an existing local evidence directory for neutral offscreen JPEG view renders. These contain synthetic subscriptions and are explicitly not desktop screenshots or physical-display evidence.

## Behavior editing and host requests

`await editor.commit(SettingsB21Edit)` uses the same store, revision check and successful `onCommit` receipt as B20. The app coordinator can call its existing `editor` directly; no new store, consumer producer or Instruments dependency is introduced.

- Order uses the shared `DockSubscriptionPreferences`, preserving missing IDs and hidden subscriptions. Native arrows and local drag/drop carry the expected order; changed membership/order invalidates a drag. Drag pasteboard data is a random local token, not a subscription ID. Reset restores catalogue order without changing aliases/visibility.
- Alias fields use `AliasDraft` and commit completed editing only. Environment, locale and context refresh keep the same surviving field and its marked text. Completed text remains an unconfirmed local draft until a successful save receipt. If another save is pending or saving fails, the draft stays visible with explicit retry feedback; finish editing again to retry, or Escape cancels it. Removing a field retires it before callbacks can save. Shortcuts are explicit local recorders; Return/IME editing in aliases is not a global key hook.
- `SettingsPageContext.shortcutObservations` binds each observed registration state to the exact chord. `shortcutPolicy(preferences:)` reuses the existing local/global matching policy; a new saved chord is not shown as registered because an old chord was. Conflicts/denial/unavailability still permit local matching when not editing/composing. Command-comma remains reserved.
- Login displays saved intent separately from `capabilities.login`. Automatic update checking is an additive v1 Boolean, default true, with explicit false retained and malformed present values rejected. `updateServiceAvailable` is an injected capability, not persisted or inferred from the checkbox. Capture hiding remains unavailable. Unaccepted ignition, macOS14 and Reduce Motion still force effective Quick Open; unavailable Hold cannot be selected and countdown is disabled.
- Optional readers save consent only and display injected observations/read descriptions. Detection, consent and actual reader activation remain separate facts. No filesystem reader is invoked.

`editor.onHostRequest` receives revision-tagged requests **only after successful explicit edits**: the existing `LoginServicePolicy` intent, shortcut-preference changes, or reset of the shared hint scheduler after all nine persisted hint flags/open/reveal counts reset. Restore/environment/context changes and failed/stale writes emit no request. This callback is not authorization for a system operation. The application owns revision/observation rechecks, its single in-memory hint arbiter, and any separately authorized backend. M0's current app coordinator still forwards `onCommit`; wiring this additional request callback is a separate composition change.

Set `MODELPLAN_B21_EVIDENCE` only when intentionally collecting neutral offscreen General/Subscriptions JPEGs into an existing evidence directory. These do not establish displayed keyboard/IME/VoiceOver, source/native pixel parity or physical-display acceptance.

## Persistence and consumers

- Create one app-scoped `SettingsStore` at an app-owned **new** preference URL. This v1 envelope does not replace Core's existing `CommunityPreferences` file (locale/favourites). M0 must choose one authoritative locale when binding them; do not introduce two simultaneous writers. Preferences contain choices and stable subscription IDs/aliases, never raw CLI data, observed login status or authorization status.
- `update(expectedRevision:_:)` validates a complete candidate and writes a bounded, private staging file before atomic replacement. Failed validation/write leaves the previous value/revision in memory; unsupported, corrupt and oversized files fail without being reset or overwritten. Missing v1 top-level choices use defaults. Obsolete/malformed onboarding progress is reconciled independently to the supplied flow in memory, without resetting unrelated preferences or rewriting the file during load. There is no migration from another file or cross-process write coordination. A caller should present load errors rather than open another store and silently reset it.
- Supply the same `OnboardingDefinition` to the store initializer and onboarding reducer. After standalone decoding, call `reconcile(in:)` before presenting a flow. Pass each committed snapshot to `EffectiveSettings`, `SettingsCatalogue`, the shortcut matcher and notification policy. Re-evaluate with current system appearance/accessibility/full-screen inputs. A preference override can force reduced effects on, not force system accessibility off.
- `SettingsPreferences.subscriptions` reuses `DockSubscriptionPreferences`; Settings, dock and cockpit share this same order/hidden set, including disconnected IDs. `presentedSubscriptionIDs(includingHidden: true)` keeps hidden subscriptions editable. Alias drafts do not commit marked IME text.
- `EffectiveSettings.visibilityPolicy` and `applying(to: DockPresence)` feed the existing dock reducer. `SettingsPreferences.applying(to: DockInstrumentInput)` supplies alias, remaining/used mode and general-window pin. Pass `redBelow` to `DockInstrumentProjection.evaluate`; critical status always uses remaining quota. An unavailable pinned period falls back to the dock's automatic selection; no window is fabricated. Number visibility does not remove event indicators; `showPercentages` is a separate consumer flag.
- Other effective choices (size, magnification, menu display, language, active-display following, names, sliver alert) are typed inputs for their eventual consumers. M0 owns real locale/display/service binding and redraw transactions. No runtime effect is claimed until these adapters exist.
- Product ignition remains quick-only on macOS14, under Reduce Motion or until the native entrance is accepted. Stored hold choice survives a downgrade; accepted product default ignition is950ms. Historical draft step IDs/gesture helpers remain for decoding and generic regression tests, not as first-run content. The current default flow is one setup page. A valid completed historical tour migrates to completed setup; incomplete/invalid progress recovers to setup without resetting other preferences or emitting effects.


## Actions and read-only data

The catalogue provides English/Chinese search, one-line titles/subtitles, choices, per-subscription data and explicit availability. Search includes both languages plus subscription alias, plan, vendor, tool and model names. A validated `SettingsStructure` supplies ordered pane IDs/titles, groups and setting keys independently of the preference/value definitions. Custom pane IDs, regrouping and reordering require no reducer changes; all existing keys must appear exactly once. Rows carry the injected pane/group identity and titles, and search also includes these injected titles. The default task65 table preserves every semantic key once in its confirmed home; custom injected tables remain supported. Duplicate vendors stay distinct by subscription ID/plan. Read-only source/CLI states are injected enums, never raw errors.

- `openAtLogin` is the app-owned user choice, **on by default**. New preferences and missing v1 fields read as true; an explicit false survives restart/upgrade. A present malformed value (including null, strings or numbers) fails closed instead of enabling the choice. The schema version and CLI contract are unchanged.
- `LoginSetting` carries both `requestedEnabled` and the independently observed `LoginServiceState` (initially not registered). The Settings row uses this pair; saving true must never turn notRegistered/requiresApproval/unavailable into enabled. The local choice remains editable when service actions are unavailable. `loginRequest` still returns an intent only (nil when unavailable), never registers/unregisters anything or optimistically reports success.
- `OnboardingOptions` reads the same canonical choice for a pre-checked **Open at login / 登录时自动打开** option. The user can untick it; apply that draft inside `SettingsStore.update` to persist the chosen login/reader booleans without resetting unrelated progress, notification consent or other preferences. Its service-status projection stays separate. The current single-page data seam supplies the shared login subtitle; it adds no view or final Settings pane table. The later app adapter owns SMAppService registration; constructing/projecting/loading/saving these models never changes a login item.
- Capture hiding stays unsupported. There is no preference switch claiming to hide from arbitrary recorders.
- CLI retention is read-only: sessions 35 days, daily totals 371 days. CLI clear, retention mutations and reader setup have no command/effect in this module.
- App-cache clear is a separate unavailable-by-default intent. Only enable it after an adapter can clear app-owned **derived caches**. It must retain preferences, aliases, order, consent, first-run progress, CLI history and the notification ledger; it must not reuse the browser study's preference-reset shortcut.
- Notification opt-in defaults off; per-kind choices alone do not grant consent. `userSetOptIn` returns one permission request only after an explicit off→on choice. Ignore late/mismatched replies. Denied/unavailable service states do not prompt in a loop. Persist the consent edit successfully before executing a returned permission effect; observe real authorization after changes.
- A notice must be live, within its semantic episode's lifetime, and have a stable subscription/episode ID. Restored/replayed snapshots do not notify. Deduplication uses kind+subscription+episode, not changing receipt times/revisions. The bounded `NotificationLedger` contains only opaque IDs/deadlines and can be stored as a separate app-owned file. Restore it before live delivery; use bounded decoding at that adapter boundary. Serialize evaluate/send/record, recheck consent/deadline immediately before sending, and record only OS-accepted deliveries. At capacity the policy suppresses new events rather than evicting live deduplication entries. Hidden project names never appear in the returned delivery. No notification is actually scheduled by this package.
- About diagnostics allow only app/CLI versions, macOS version, allowlisted observed-enabled reader IDs and at most8 typed recent error codes; no paths, aliases, project names, IDs or raw CLI output. Feedback is a public issue-template URL, not an automatic submission. The app supplies audited bundled third-party license notices. Intel carries the explicit untested warning.

## Single-page first run and paced hints

`FirstRunPage` projects ephemeral detected subscriptions (including0/1/6), explicit reader observations, optional reader consent (off by default), privacy, the canonical login choice and its exact subtitle. Detected/optional readers never run here; consent does not imply activation. `SettingsStore.completeFirstRun` commits the options and completion before returning typed effects. Done closes the popup/reveals the dock, or returns standalone preview to Settings. See what's here opens the cockpit and latches the **same** Option-help model; Esc/click releases it. A stale revision or failed write returns no effects. Completion uses the task65 store definition; no Back/Next/tour UI is implied.

`FirstUseHints` remains the single app-wide timer-free arbiter. Nine once-only flags plus `opens`/`reveals`, each clamped to0…2, are its only persisted hint progress. Legacy `cockpitOpens` migrates to `opens`; obsolete first-pin state is ignored and disappears on the next successful save, with no invented reveal history. Loading does not rewrite the file. Cockpit/reveal identities, budgets, rests, target IDs, deadlines and placement are transient. Priority is ignition → detach → Option → shutter (second open) → field → drag → page → pinned → trial. Initial detach/Option/shutter/field/page/trial offers wait for captureReady; pinned/drag retain their existing lack of that capture barrier.

Ignition keeps its500ms dwell and reserves the first eligible Dock reveal; while unseen it reserves subsequent reveals too. Drag is eligible from reveal2 without any pin prerequisite. `beginDockRevealDwell(at:)` arms the same500ms source reveal dwell for whichever of ignition/drag is reserved. A pinned card cannot spend a closed-Dock reveal while either reserved hint is pending or unplaceable. An ignition shown on reveal2 spends that reveal, so drag waits for the next reveal. A genuinely new nonnil host identity increments the corresponding counter, not a pin/focus/repaint transition. Closed pinned-card help uses the Dock budget; any shown hint with an active cockpit also spends its open budget.

Trial is no longer a direct request or drag trigger. Feed the shared arbiter `beginTrialRest(on:at:)` with an opaque `TrialHintTarget` identifying the **travel** (the cap uses that same target). It returns a `TrialHintRest` token/deadline. Repeated stationary entry on that target keeps the deadline. Actual movement cancels/restarts; leaving, pointer-down, key input, focus loss or removal calls typed `cancelTrialRest(_:reason:)`. A token-specific cancellation from an old/removed target cannot cancel a newer rest; use nil only for app-wide cancellation such as focus loss. The timer callback calls `offerTrialRest(_:placeable:at:)`, which validates the current token and returns through the same priority/placement arbiter, not a per-view queue. The returned offer may be a higher-priority kind; a trial offer carries its `trialTarget` for travel anchoring. Ordinary `request(.trial)` and `beginDwell(.trial)` do not create a trial offer. No model/session/comparison mutation is available here.

The host owns one clock/timer and can reschedule from `nextDeadline`; views must not own parallel arbiters. Cancellation retires pending/unshown trial offers without spending state, while already-confirmed hint lifetime/seen/budgets remain real. A context/capture/map change invalidates a pending rest; restored capture needs a fresh trial rest. All actual event delivery, target lifecycle and placement belong to adapters. Exact official zh/en hint/dismiss copy is injected privately by kind; this public model contains no official presentation strings.
A placement **offer spends nothing**. The adapter must confirm only after the shared overlay is actually placeable/visible; rejection, missing placement or stale context spends neither flag nor budget. A confirmed hint lasts5s, then ends without an automatic tour; unseen lower-priority requests need their next eligible trigger/context. Keep resupplying currently eligible anchors as `placeable`, never stale hidden ones. Identity changes still dismiss all transient hints/offers/dwells. With the same identities, disappearing card/guarded-capture conditions invalidate only the affected offer/presentation: an unshown offer spends nothing; a shown hint keeps its seen flag and budget spend. Pinned/drag retain the original absence of a capture barrier. Reduced Motion has no fade; changing it does not restart the lifetime. Hint dismissal/reset has no cockpit/card mutation API. Reset clears all nine flags, both counters and current budgets/rests without manufacturing a new open or closing underlying windows.

`SettingsDiagramInput` and `SettingsDiagramPlayback` expose the five semantic inputs and one finite400ms transition, static with Reduce Motion. There are no drawing paths, assets, idle loops or layout mutations. Quota-window preview uses the last changed available subscription, otherwise the first; percentage-off retains the event dot.

## [M0 needed] consumer / system adapter

- Own one store and shared hint overlay. Feed actual open/reveal identities, current pin state, capture completion, focus/map state, typed trial-rest events and monotonic clock. Preserve underlying windows on hint dismissal; use the returned hints preferences for bounded persistence. `resetFirstUseHints` commits reset first; then reset the in-memory arbiter's budgets/dwell. If persistence fails after an already-visible hint, retain its in-memory seen state instead of repeating it; report persistence failure without claiming it was saved.
- Dispatch first-run navigation/help effects only after successful commit, and deduplicate callbacks by the returned revision. Bind `OptionHelpState` to the existing Option map, not a second overlay.
- `commitOpenAtLogin` returns a revision-tagged intent **after** persistence. At execution, recheck current revision/choice; stale requests must not act. `LoginServicePolicy` never requests service changes on restore or system observations, never reopens an externally disabled item automatically, and keeps requiresApproval/unavailable states truthful. Actual SMAppService register/unregister, background-item notices, OS observation and failure UI belong to M0/app/backend; no backend exists here.
- Root manifest/CI/app registration, actual reader activation, placement/focus/VoiceOver/keyboard controls and all official drawing remain outside this lane. Reader consent is storage only, not a CLI reader-enable action.

## Remaining app binding

The Settings surface, B20/B21 edits and finite line illustrations are implemented here. App entry, actual Dock/Cockpit redraw, the shared hint-reset bridge, global registration, login service changes, notification requests and cache deletion need app adapters and corresponding native acceptance. Remaining setting edits and first-run views are later increments. Actual keyboard/VoiceOver/IME and display/system-service checks remain separate from the offscreen tests.


## Hint consumer dependency boundary

The Settings package already depends on the root native package for Dock choices. A root `ModelPlanInstruments` target must **not** add a reverse dependency on Settings to use hint types; that would introduce a package cycle. M0's composition root should own the shared `FirstUseHints` and translate M3's semantic fader entry/cancel events into the typed API above, forwarding offers to the existing shared overlay. No shared target/Package/CI change is authored in this increment. M3 must remove drag-based trial requests and must not implement a second rest timer/queue/ledger. Official copy and native-title policy remain external inputs; this increment adds no Settings view or tooltip.

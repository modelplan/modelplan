# Verification Dock scenarios

These synthetic app-server snapshots are inputs for the separately compiled verification application. Copy one JSON file into the synthetic HOME as `.modelplan-verification-rows.json` and create `.modelplan-verification-home` containing exactly `MODELPLAN VERIFICATION HOME`. Set `HOME` and `CFFIXED_USER_HOME` to that same synthetic directory; the application verifies its Application Support location is inside it before reading Settings. While the app runs, replace the JSON atomically with a valid snapshot whose `sequence` is greater than the preceding snapshot; the verification client checks for a changed file each second. The existing fixtures all start at sequence 7, so increment a copy before switching scenarios. Do not use a real account or profile.

The scenarios cover mixed quota levels and overflow, single weekly windows, announced and confirmed public resets, and retained stale readings. The 16 button interaction states require the T2 appearance and its actual interaction driver; row snapshots alone do not set button state. Reset signals and ring-role projection require #401; the T2 appearance requires #397.

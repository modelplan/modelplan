# Standalone consent and first-run core

This is the first main-based slice extracted from #256 under the coordinator's split instruction. It contains the v0.5.43 identity-gated consent port, canonical backend, normal Community entry/Settings factory, first-run consent choices and safe missing-data navigation. Dock companion/placement producers and consumers remain in #256; this slice preserves main's existing surface composition.

`CommunityApp` creates one bundle-gated port/backend and the same desktop transport gate consumed by the existing runtime. Its factory returns the integration retained by `CommunityDelegate`; that integration uses the same Settings application/editor. Canonical consent readback, not a grant receipt or UI switch, admits normal desktop reading. Component availability and permission/quota/subscription facts remain separate. The Claude Keychain choice is initially unchecked, separately confirmed, allow-only, and restricted to the supported selected native Claude row.

The bundle-consistency producer verifies known raw v0.5.43 inputs, writes version/source hashes plus actual final helper hash/resource pin, and both later reseal paths refresh those last two records. This is consistency, not standalone signature/provenance or owner-reader acceptance. Missing/old/mismatched inputs remain unverified. No package/sign/helper/App run is implied by source or synthetic tests.

About reads app version from the containing Info.plist and numeric OS version from ProcessInfo. Its CLI status describes whether the component has been verified; it does not claim successful canonical/account reads. A fresh-install canonical read failure leaves the connection snapshot unknown and offers a local About/instructions action.

A nonzero `cleanup_pending` write response is accepted only as a matched, bounded committed-denial receipt: UUID, pending IDs and explicit deny scope must match. The backend then obtains current canonical state, preserves existing verified membership/quota facts from the same editor, enforces its generation floor and retains incomplete-cleanup metadata independently. The UI shows current permissions plus the last cleanup report and a local About action whose native row displays a selectable public URL for the CLI's manual disconnect instructions, even with no host URL-opener. No automatic cookie/credential cleanup or retry is performed. A later explicit Forget may verify completion. If post-mutation canonical readback is unavailable after either a matched successful receipt or cleanup-pending receipt, current consent/preview are withdrawn while existing verified membership/quota facts are kept; no revoked/current-permission or deletion success is invented.

The private Beta07 About producer should use the same makeSettingsContext helper when M0 integrates this core with the remaining Dock factory. The retained Settings reference and idempotent construction boundary remain available for RELPIPE; its actual hook/checker, real package/smoke and ten-step owner journey are separate gates. Existing #256 history is preserved and follows main through normal merges.

Provider `hosts` are bounded display metadata, not network admission rules. Legacy strings may contain HTTPS URLs, trailing parenthetical notes or free labels; the decoder also accepts structured host/note entries and an additive `hostDetails` fallback. Legacy labels remain preferred when present so local-only descriptions are preserved. The shared Settings projection strips HTTPS user info/path/query down to its hostname, retains the note, and preserves non-URL labels. Both canonical and direct snapshot boundaries retain the 32-entry/253-byte and control-character checks; consent generation, reader eligibility and Keychain choices are unchanged.

The recorded v0.5.43 synthetic-HOME stdout fixture is replayed through the real consent adapter, backend and Settings factory without executing a helper. Its provenance version must match the independent native helper pin; synthetic URL/structured and mounted-choice cases supplement the exact one-tool capture.

Settings and first-run connection surfaces share the same controller, but each tags its requests with a presentation ID. Hiding an inactive surface cannot retire another caller's inspection or confirmation. Lifecycle suspension retires UI work and late receipts without claiming a user cancellation; an explicit Cancel retains its cancellation message. A queued Check or Confirm that is hidden before dispatch performs no inspection or confirmation and cannot cancel another surface's pending confirmation. After confirmation starts, the confirming surface owns the in-flight UI receipt; hiding the original initiating surface cannot retire it. These IDs never enter the app–CLI JSON contract or grant authority.

Subscription catalogue ownership is separate from canonical consent. `CommunityPlacementBinding` forwards the actual Dock catalogue, including an authoritative empty catalogue, into the shared editor. A canonical controller observation cannot replace that catalogue: consent readback does not report complete membership. Explicit full-runtime `CommunityConnectionFacts` applied through `flow.apply(...)` retain their existing validated projection path. This avoids startup/readback ordering erasing visible rows without inventing subscription references.

订阅目录与共享授权是不同事实。`CommunityPlacementBinding` 将实际 Dock 目录（包括明确的空目录）送到同一个 editor。授权回读只更新连接控制器，不能据此覆盖订阅成员；显式的完整运行时事实仍通过 `flow.apply(...)` 走原有校验投影。这样启动和回读的先后顺序不会擦掉设置行，也不会虚构订阅引用。

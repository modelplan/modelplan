# Native shared selection assembly

`ModelPlanAssembly.SelectionAssembly` is a pure bridge between a current `JoinedSnapshot`, `ModelPlanSelection` and the instrument package's `InjectedModelSelection`. The root native build/test command includes its tests. Core, selector and instrument modules stay independent; only this assembly target depends on all three.

Each evaluation rechecks the existing personal deadline with an expiry ledger, retains the incoming join's availability verdict, then invokes the one shared selector. Published lineage/default flags and pick tags are passed verbatim. Explicit published dominance kinds are mapped without comparing ability, cost or versions. Conflicting lineup contexts produce conflicting input records, allowing the selector to abstain rather than promoting an arbitrary context. The same immutable ordered IDs, publication/revision/scope and recent-use provenance are injected into instruments; field/chart/row prefixes remain the shared selector's properties.

Offerings and historical use are explicit native-adapter evidence inputs. Account/harness bindings, source-wide token buckets and current configuration do not prove entitlement or per-model historical subscription ownership/time. Stale offering evidence becomes unknown; use requires verified subscription attribution and usable evidence. Missing facts are preserved as unavailable/unknown, not populated from names, scores or current bindings. This bridge reads no personal files, runs no CLI commands and adds no schema fields.

Callers must obtain a current store join for each refresh: its public-feed availability/expiry verdict cannot be reconstructed from an old publication object alone. The assembly independently latches the personal lifetime even for a retained join. It does not create a second public cache or invent a publication TTL. A missing revision or unavailable selection cannot become a trusted instrument page.

This is the typed composition seam, not a completed UI/runtime data-source binding. Producers of canonical offered-model facts and exact attributed per-model use events still need an existing verified source; absent data must remain unknown. Do not synthesize a seven-day event timestamp from a daily bucket or a session's latest time. There are no official visual resources, app side effects, permission requests or CLI mutations here.

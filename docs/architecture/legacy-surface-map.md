# Legacy desktop surface map

Inventory date: 2026-10-29. Evidence is pinned to public main at [`d223cca6a4d6`](https://github.com/modelplan/modelplan/commit/d223cca6a4d6d695141e3a2b66739c3acc10ad48). This is a read-only migration inventory, not approval to remove a command, package, fixture, test or asset. No runtime behavior is changed by this document.

The retirement unit is the old app adapter and its consumers, not everything with “desktop” or “contract” in its name. The packaged native constructor still builds `BundledCLI` and `ConsentGatedDesktopTransport`; the Tauri shell separately executes `desktop --json`. Public plugins and the Skill use several of the same CLI commands. The new server itself uses the consent, quota, publication, history, store and rows implementation.

## Reading the decisions

- **Stay**: a current public, plugin, engine or test-tool consumer survives app migration. U6/U8/U10 do not authorize deleting that contract.
- **Adapt**: detach the old app binding, preserve its surviving consumers and move app semantics to the new contract. A whole directory is not a deletion unit.
- **Retire after gates**: an old native adapter, duplicate derived state or frozen app test can be removed once its replacement is reached from the packaged production constructor and passes the relevant acceptance gate. “Replacement” below is the target call path, not a claim that UI wiring has landed.

The gates are U6 (Dock/menu render canonical rows; refresh uses U3b; the fence test precedes removal of merge code and `onCanonicalInvalidated`), U8 (per-scope consent, revoke/Forget including undetected tools, diagnostics and plugin install), and U10 L2 (the integrated packaged candidate, including the completion edges and smoke/review requirements). Frozen legacy CI can be removed with the legacy app in U6; portable regression coverage is retained in the engine/new UI. Adapter retirement that also needs Settings or packaging waits for U8 and U10 evidence. A separately surviving Tauri or documented CLI consumer needs its own migration decision.

[delivery and completion contracts](https://github.com/modelplan/modelplan/blob/d223cca6a4d6d695141e3a2b66739c3acc10ad48/docs/architecture/foundation-v2.md#L473).

The plugin cross-check uses actual calls and documented Skill commands, rather than treating all CLI commands as plugin APIs. The publication-reader compatibility check covers `sync`, `models --json --offline` and the Codex publication reader; it does not establish a plugin consumer for every command. Public evidence for that reader is [createReader](https://github.com/modelplan/modelplan/blob/d223cca6a4d6d695141e3a2b66739c3acc10ad48/codex/data.mjs#L17). Local helper discovery and user-facing CLI help remain separate consumers.

Three replacement gaps are explicit: the Go constructor registers `publication/get` and `plugin/install`, but the current Swift client's corresponding provisional result APIs fail closed with `featureDecode`. The Swift EngineClient interface also has no cockpit/query method yet. These gaps remain work for the app integration; signatures do not complete U8/publication/cockpit UI migration. ## Reviewable retirement boundaries

1. U6 removes the app's personal/publication merge and duplicate row/reason classifier only after canonical row and fence tests pass through the real app constructor. Keep all public CLI/plugin consumers and Tauri compatibility until separately migrated.
2. U8 removes the old tool-level consent/CLI port and dual admission callbacks after scoped grant/revoke/Forget, cancellation, cleanup-pending and diagnostics/plugin flows pass through the new UI. A provisional JSON result signature is not that evidence.
3. U10 validates the packaged helper, signing/credential identity, production entry point, lifecycle/clear order and integrated L2 scenarios. Preserve preference migrations, input/accessibility, notices and publication/selection semantics.
4. For each proposed deletion, update this map with the surviving consumer check and replacement acceptance evidence. Do not infer deletion authority from a merged interface or from a frozen test.

These boundaries follow the [unit completion and old-path deletion rules](https://github.com/modelplan/modelplan/blob/d223cca6a4d6d695141e3a2b66739c3acc10ad48/docs/architecture/foundation-v2.md#L462) and the [candidate completion gate](https://github.com/modelplan/modelplan/blob/d223cca6a4d6d695141e3a2b66739c3acc10ad48/docs/architecture/foundation-v2.md#L488). This inventory itself deletes nothing.

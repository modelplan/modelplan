# D590 reader contracts: translation and upgrade gates

Companion to [the auto-detection design](agent-usage-auto-detection.md); implementation awaits approval. FEEDFIX owns these reader/fixture contracts. CLIJIT consumes the additive DTOs/status codes and publication schema; App/client lanes render them. Research only: no real credentials, Keychain queries or authenticated provider calls.

## Pinned CodexBar JSON, not UI assumptions

Baseline: **0.81.0 / `ee890b5f392e70d6e20162d3e95cf9f1be265b60`**. The executable's effective schema is its [CLI payload encoder][P], [UsageSnapshot/RateWindow encoders][U], [credits models][C], [provider cost][S], [detail rows][D] and provider-specific Codable fields. Record field/type/unit/provenance coverage for every provider and candidate release; a Swift property is not necessarily emitted JSON. In this pin `usage.costUsage`, `opencodegoUsage`, Grok/Claude reset-credit objects and several live-only fields are **not encoded by UsageSnapshot**. Do not invent those JSON locations. [OpenAI API usage][A], [dashboard][O] and [Mistral models][M] are encoded, provider-specific families to audit.

Today `parseCodexBar` only translates percentage lanes, discards estimated values and `applyCodexBar` rejects accounts without windows. Replace those assumptions: a valid balance-, count- or spend-only reading is useful; unsupported translation must say **“not supported yet”**, never measured zero. Provider errors remain errors, not successful empty readings. Require the requested provider **and account/profile**; multiple records cannot silently select the first login or CodexBar's default provider.

| Encoded source in 0.81.0 | ModelPlan destination and rules |
| --- | --- |
| `usage.primary/secondary/tertiary`, `extraRateWindows[].window` | `Account.windows[]`; preserve duration, reset, bounded label/model/pool ID and observation time. `isSyntheticPlaceholder:true` is not measured zero; `usageKnown:false` means null usage even when reset metadata is present. `quotaLimit/quotaUnit` retain absolute allowance/unit, never infer an exact request count from a rounded percentage. |
| Top-level `credits.remaining/updatedAt`, `balanceReadSucceeded`, `creditsAvailable`, `balanceIsWorkspace` | `Account.credits.balance/observedAt` for the supported credit wallet, plus explicit unit/scope/availability metadata. A false read-success flag with numeric zero is **unavailable**, not a $0 wallet. Personal/workspace caps and wallets remain separate; missing timestamps never become “just fetched.” |
| `credits.codexCreditLimit.{used,limit,remaining,remainingPercent,resetsAt,updatedAt}` | A **credit-denominated cap meter**, separate from the wallet and from reset cards. Use a supplied monthly cadence only for that provider contract; a title alone cannot establish a period. Keep its cap reset/age independently. |
| `usage.providerCost.{used,limit,currencyCode,period,resetsAt,updatedAt}` | Actual USD spend/budget → `Window.kind:"spend"`, `usedUsd/limitUsd`; zero/non-positive limit means no known cap, not exhausted or infinite allowance. Non-USD money and non-money `Credits`/`Quota` units require typed amount/unit fields; no FX conversion or dollar relabelling. `personalUsed` is an individual's contribution, not an additional pool to sum. |
| `usage.providerCost.balance/balanceUpdatedAt/balanceIsWorkspace/balanceIsUnavailable` | Separate typed balance(s) with their own age/scope; do not derive prepaid balance from budget minus spend. An explicit unavailable balance invalidates its current value, not another working meter. `nextRegenAmount` is provider-reported regeneration metadata, not purchased credit or a reset action. |
| `usage.details[].rows[].{id,usageValue,progress.used,progress.total}` and window `quotaLimit/quotaUnit` | Provider/version-specific mappings identify balances, spend, request/MCP counts or token allowances. True request counts → `Window.requests` with integer used/limit/remaining and explicit unlimited/reason. Fractional credits stay credits. A numeric row alone has no universal unit: require a documented row ID/contract. Presentation `value/secondaryValue` strings are not generic numeric APIs; only a strict provider-specific formatter grammar with known unit/locale may be supported, preserving rounding/confidence. Otherwise the shape is unsupported. |
| `openaiDashboard.creditsRemaining/creditsAvailable/balanceIsWorkspace/codexCreditLimit`, `creditEvents` and `credits.events` | Same-scope wallet/cap/observed credit usage, with explicit precedence when the top-level credits object already describes it. Never count both. Strip email/account IDs, event UUIDs, purchase URLs and all redemption identifiers. Event spend is history, not a remaining balance; never subtract it again. Unknown workspace binding cannot inherit a personal wallet. |
| `usage.openAIAPIUsage.daily[]` (`costUSD`, `requests`, model/request aggregates, explicit dates); `usage.mistralUsage` (`totalCost`, currency, period, credits wallet/notes/ongoing use) | Dated spend/count accounting, not subscription entitlement. Preserve time range and account/project scope without raw IDs. Mistral's `max(0, wallet + credit notes − ongoing use)` may be derived only from complete, finite, same-currency fields, with that formula/provenance explicit; incomplete/non-finite components remain unknown, never the upstream formatter's fallback zero. Do not fabricate a limit from historical totals. |
| `usage.copilotMeteredZeroCredits`; `usage.throughput`, subscription dates | The Copilot marker preserves an observed zero credit entitlement only under its verified metered-seat contract; false/missing does not imply unlimited or zero. Throughput is performance, not request allowance. Subscription renewal/expiry metadata cannot manufacture a quota window or balance. |
| Top-level `resetCredits.{available,nextExpiresAt}` / encoded `usage.codexResetCredits` | `Account.cards` count/expiry only; choose one authoritative representation and drop IDs. A compact earliest-expiry summary cannot invent the expiry of every card. Reset inventory is neither money nor spendable usage credits. Never call redemption/consume. |
| `usage.dataConfidence` | Preserve confidence independently of availability/freshness: `estimated` stays visibly **estimated**, never promoted into measured quota/pace or an entitlement binding. `unknown`/absent is not silently `exact`. Retain supported estimated fields with provenance; an estimated amount still needs a known unit/scope. |

**Additive DTO work:** retain existing `Account.credits`, `Window.usedUsd/limitUsd`, `Window.requests` and `cards`. FEEDFIX proposes optional `confidence`, `meteringMode`, field-level availability/provenance, currency/unit/scope on credits, `balances[]` for distinct wallets, amount/unit fields for non-USD/non-cash meters, absolute quota counters and `requests.remaining`. No existing field changes meaning; unsupported older clients see unknown rather than mislabelled dollars. Coordinate CLI/desktop wire-capability projections with CLIJIT before enabling new shapes. Do not claim credits-history capability merely because the current snapshot includes events.

Finite numeric values, explicit zero vs null, source units, observation/expiry and membership scope are required. Decimal currency handling must avoid precision loss; sign conventions are provider-specific (e.g. a negative accounting balance is not globally “abs cash”). Do not parse arbitrary reset descriptions into money/counts, apply universal denominators, reprice tokens, or copy opaque provider text. Known fields can be shown with a partial-translation reason when another field is unsupported; if nothing useful can be faithfully represented, the **provider** is “not supported yet.” Keep the last-good historical reading with its age when a formerly supported shape breaks.

## Every-provider daily contract gate

Extend `TestLiveCodexBarContract`, `scripts/pin-codexbar.mjs` and the **daily** `codexbar-pin` monitor. The test set is the union of candidate registry IDs and still-active pinned IDs, **not** the current five-provider allowlist. Verify equality between registry, detector-port inventory and result matrix: no missing provider is silently passed or skipped. Removed/renamed providers are recorded explicitly; do not let an unknown provider flag query CodexBar defaults.

For each provider/platform/source, record candidate version/hash, adapter mapping version, test mode, fixtures/coverage, stable result and reason. Use the actual verified candidate binary for safe unauthenticated JSON-envelope/error smoke checks; never import host credentials, invoke login or perform inference. Run only in an isolated synthetic home/config/environment with no Keychain/installed-tool access and no authenticated vendor traffic. Sources that cannot be invoked safely, including sign-in-only sources, use independently written synthetic success/error fixtures checked against that **candidate's** encoder/contract. Exercise the real encoder with fake responses where supported; compare source schema and golden fixtures otherwise and label that weaker evidence honestly. These fixtures prove compatibility, not a real-account pass or permission to remove beta.

Each provider has semantic fixtures for its available shapes: percentage/other/model/MCP windows, true zero/null/unavailable, balances without windows, spend without cap, request-only/unlimited, units/currencies, estimates, partial data, multi-account ownership, overage/reset expiry and unsupported shape. Assert the expected ModelPlan fields and status, not merely JSON parsing or an error envelope. Record unverified new shapes as blocked. Tests never accept a guessed number to make the matrix green.

**Provider-scoped upgrade:** passing providers advance; a failed provider retains its last passing version/platform hashes and mapping, even when the default advances. Proposed additive `codexbar.providerOverrides[providerId]` is either a complete `{version,sha256}` pin or `null` (no safe bridge version yet). Persist a provider compatibility/result map in the reviewed proposal. Native reading can continue when only that provider's bridge upgrade is blocked. Store artifacts by version/hash; do not remove an older verified binary still referenced by any provider or rollback state. Enforce `minCli` for the override-aware router so older copies cannot silently use the new default for a held provider.

Example: candidate B passes Cursor but fails Kimi → default B, Kimi override A; both use verified artifacts, and only Kimi reports its held upgrade. A new provider with no passing A remains “not supported yet,” not routed to a random fallback. A bad archive/checksum/registry-integrity result blocks all uses of that unverified artifact/platform; a provider-specific contract failure does **not** block unrelated passing providers. The daily job always collects individual results and opens one reviewed pin/catalogue proposal including holds; it must not abort the entire proposal at the first provider failure or hide failures under a green aggregate label.

## Claude Code passive current-session reader

**Owner requirement, 2026-10-27:** Claude detection, login quota and current-session metadata work with no ModelPlan plugin, hook or status line installed. Implement session reading separately from login quota, following the bounded passive approach of `readCodex`. Optional extra snapshots override neither native quota nor native session fields, even when a field is unknown; they cannot select the current session or grant access. Unrelated existing optional metrics may remain separately attributed.

**Evidence and limits.** Official [session documentation][CS] defines the project JSONL location and `CLAUDE_CONFIG_DIR` override. [Application-data documentation][CDIR] describes main/subagent transcripts and warns that their bodies contain sensitive content. The official SDK's [session reader][CSP] confirms `sessionId`, `uuid`, `parentUuid`, `isSidechain`, `isMeta` and `isCompactSummary` conventions. This is not a stable, complete on-disk schema. The [published TypeScript SDK 0.3.301][CSDK] (Claude Code 2.1.301) supplies additional first-party session-selection evidence; do not equate its live stream types with persisted records. Retain versioned evidence and handwritten fixtures for each accepted transcript shape. No host transcript was inspected or generated for this note.

| Value | Accepted record field and meaning | Unknown / excluded evidence |
| --- | --- | --- |
| Model | `type:"assistant"`, `message.role:"assistant"`, **`message.model`**: the responding model ID. | Missing/invalid ID stays unknown. Internal `<synthetic>` responses and error placeholders do not establish a responding model. No alias-to-latest guessing or global default. |
| Reasoning effort | **Top-level `effort`** on that assistant record: reported level, e.g. `low`, `medium`, `high`, `xhigh`, `max`. An [upstream reproduction][CE] explicitly reports this field on 2.1.283; treat it as an observed internal format, not a documented stable guarantee. | Absent/null/unrecognised shape stays unknown. Do not guess `message.effort`, treat settings `effortLevel` as per-turn evidence, inspect thinking text, infer from token counts, or assume a model's default. Any new object/alias/numeric representation needs separate first-party evidence and a fixture before support. |
| Fast / speed | **`message.usage.speed`**: `fast` → `fastMode:true`; `standard` → `fastMode:false`. The [first-party Messages usage type][CUS] defines the actual request speed as those values or null. This is **observed turn speed**, not proof of the next turn's toggle. | Absent/null/unknown value stays `fastMode:null`. `service_tier` is not speed; `priority` is not Fast. Saved `fastMode` preferences, model name, latency and price are not current-session evidence. Do not assume live SDK `fast_mode_state` is written to the transcript. |

The [Fast documentation][CF] distinguishes a saved preference, session opt-in and a toggle that can affect the next turn. Therefore label this **last observed session state** with its original timestamp. A setting changed after the latest assistant turn is unknown until recorded; a recently modified file is not a live/focused-session guarantee. Model/effort/Fast come from **one** selected turn, never a mosaic of newer model plus older known effort/speed. Field absence in a newer turn clears the old field to unknown.

**Discovery and selection.** CLIJIT supplies only authorised profile roots and an optional explicit caller session selector. Within `<root>/projects/`, scan main session files with bounded depth/file count/bytes/deadline, regular-file and symlink-escape checks; do not open history, debug logs, tool-results, memory, orphaned/superseded copies or subagent trees. Never execute Claude or shell commands to discover state. Traverse all eligible sessions within the declared bound; if the budget prevents a conclusive newest selection, report incomplete/stale selection rather than assert it is current. Parsing uses an allowlisted header projection and skips all message content/tool payloads, including arbitrary nested objects resembling metadata.

Group by profile and session ID; validate filename/header agreement and reconstruct eligible main-chain ancestry using transient `uuid/parentUuid` where needed for forks/resumes. Deduplicate repeated streaming blocks by `message.id`; take the newest complete assistant record on the selected main chain, with deterministic append-order tie handling. Later partial blocks cannot splice fields from another turn; if same-message fragments conflict, mark the affected value unknown. Ignore sidechains, `agentId`/team workers, compaction summaries, meta/progress records and synthetic/error responses. Use source timestamps for freshness/ordering, never a copied file's mtime; malformed/truncated final lines leave the previous complete observation aged, not freshly observed. No assistant record means no observed state.

Keep each session's latest observation independently, then select the **newest interactive** session by its latest eligible assistant timestamp as **`recent-thread`**. Read known transcript `entrypoint` metadata and `sessionKind` only for classification: the pinned SDK excludes `sdk-cli`, `sdk-ts`, `sdk-py` and `daemon`/`daemon-worker` from interactive session pickers. These exclusions and sidechain filtering are required; a main-file location alone cannot prove interactivity. Positive attended/legacy classification must have versioned first-party evidence; unclassified sessions remain origin-unknown and cannot displace a confirmed interactive session. No interactive candidate means unknown attribution, not a fabricated recent thread. A matched explicit caller selector permits **`current-thread`**; a missing selector match reports that fact and may separately offer `recent-thread`, never relabel it current. No foreground-window/process inspection or hook is required.

**Storage and admission.** Retain only model, effort, nullable Fast and `HMAC-SHA256(installation key, domain + opaque profile ref + session ID)`, with existing observation/attribution/source status metadata. No plain SHA: today's `SessionKey` helper is unkeyed, so the new PR must use the existing installation-key facility and version/migrate its own cache without exposing old raw IDs. If the key is unavailable, do not persist the session identity. Raw IDs, ancestry, paths, offsets/inodes and classification fields are transient; no transcript copy or path-based persisted index. Project-label preference may permit the existing local short label only; labels off/unreadable suppress and purge it. Full paths, encoded project-directory names, titles, prompts, responses, thinking, tool inputs/results and arbitrary provider text never enter cache/output/errors/doctor. A synthetic canary in each sensitive field must be absent from all outputs and persisted bytes.

Validate projected fields as bounded model identifiers, supported effort levels and a nullable Boolean; reject arbitrary text, custom endpoint/account-bearing resource IDs and malformed values rather than passing them through. The inspected TypeScript package carries Anthropic's reserved-rights/legal notice, not CodexBar's MIT licence: it is read-only protocol evidence, **not vendored code or a new dependency**. Implement the parser and fixtures independently; retain applicable notices if any later reuse is proposed.

This credential-free reader works in Automatic and Passive-only under the single consent, independent of Keychain denial/login expiry and the five-minute **network** quota gate. `MODELPLAN_READERS=off`, disconnect/revocation and App hidden/asleep rules suspend new scheduled reads; no always-on watcher is necessary. Missing/denied transcripts do not trigger a plugin/status-line prompt and do not erase valid account quota. Conversely a session model does not prove a subscription/account binding or remaining quota.

## Section 9 result contract and validation

Keep **availability, confidence, freshness, billing mode and beta** as independent fields so combinations remain truthful. These are stable codes for CLIJIT/App localisation, with one next step:

| State | Display / next step |
| --- | --- |
| `not_detected` | No tool detected / Missing your tool? Tell us. |
| `consent_required` / `privacy_blocked` / `off` | Not enabled / review consent or privacy settings; never a background prompt. |
| `denied` | Keychain access denied / explicit **Retry in Settings** only; all CLI copies retain the denial. |
| `expired_login` | Open the named tool to refresh; no token repair or alternate-account hunt. |
| `not_supported_yet` | Not supported yet / report tool and version; no numeric placeholder. |
| `unbound` (membership) | Reading found, subscription unverified / retain the source reading and safe reason; never invent a subscription card or report the source missing. |
| `rate_limited` / `network_error` / `upstream_changed` | Wait until stated retry time / check connection-proxy / pending supported fallback, respectively. No credential/error-body dump. |
| `stale` | Last reading at its original time / refresh when needed and allowed. |
| `estimated` (confidence) | Estimated, with source/provenance; never an exact quota bar. |
| `pay_as_you_go` / `organisation_managed` (billing mode) | Pay-as-you-go / managed by your organisation; money/counts only when returned, never 0%/100% manufactured windows. Missing data alone cannot prove an organisation plan. |

FEEDFIX PRs must exercise Automatic/Passive-only/off admission, persistent denial across restart/update/fallback/item rename, multiple account/profile refs with one provider-wide call gate, proxy propagation to native clients/CodexBar/RPC children and helper downloads, beta/mapping metadata, and catalogue/artifact rollback. CLIJIT owns environment/consent persistence, system-proxy context ingestion, publication admission and doctor/update output; FEEDFIX supplies typed results and honours those inputs before any file/Keychain/subprocess/network operation. Synthetic tests on this worktree never query real credentials or provider accounts.
